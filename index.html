01 What it looks like

Your whole site in a JSON file. Compressed keys. Every token earns its place.

llmr.json ~1,600 tokens for 21 blog posts
{ "v": "2.1", "s": { "d": "raphaelreck.com", "a": { "n": "Raphaël Reck", "r": "IT_sys_sw_consultant" }, "llms_txt": "/llms.txt" }, "p": [ { "id": "when-webservices-lie", "u": "/blog/when-webservices-lie.html", "d": "2025-08-30", "tg": ["drupal", "debug"], "rt": 9, "cb": 24, "sum": "Drupal hooks firing too early, web services returning wrong data." } ] }

02 Real numbers, not estimates

Measured on raphaelreck.com: 21 blog posts, 93 code blocks.

raphaelreck.com • measured april 2026
Original HTML (all pages) 633,997 bytes
LLMR file 10,974 bytes
Reduction 98.3%
HTTP requests 21 → 1
Estimated tokens ~158,000 → ~1,665

LLMR is an index with summaries, not a content mirror. AI systems use it for site comprehension and discovery, then fetch individual pages when they need full text.

03 Two files, two jobs

llms.txt is the curated front door, llmr.json the complete index. Serve both: each one links to the other.

How llms.txt and llmr.json split the work, and how each file links to the other
Aspect llms.txt llmr.json
Role Curated front door Complete structured index
Format Markdown JSON with compressed keys
Lists The pages worth reading first Every page
Per page Title, link, one-line note Type, date, summary, keywords, read time
Agents use it to Get their bearings Search and filter by type, date or topic
Links to the other ## Optional → llmr.json s.llms_txt → llms.txt

04 Install

Pick your platform. One command.

$ pip install llmr-generator && llmr generate ./my-site
$ npx @open-llmr/generator generate ./my-site
Download from wordpress.org/plugins/open-llmr
$ composer require open-llmr/laravel && php artisan llmr:generate # coming soon
$ drush llmr:generate # coming soon

Then add to your HTML:
<link rel="llmr" type="application/json" href="/llmr.json">
